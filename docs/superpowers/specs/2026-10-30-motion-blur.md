# Motion Blur — Design Specification

## Intent

Implement the already-declared `localcut.motion_blur` effect as a real temporal effect in LocalCut, preserving preview/export parity and Android mobile memory limits.

The effect must not be implemented as Gaussian blur. It must combine pixels from real frames over time so motion generated by source video or by LocalCut transforms/keyframes produces temporal trails.

## Existing contract

`EffectRegistry` already declares:

- typeId: `localcut.motion_blur`
- category: `MOTION`
- `shutterAngle`: `0..360`, default `180`
- `samples`: `1..64`, default `8`

This contract is preserved for saved-project compatibility.

## Goals

- real temporal accumulation, not spatial blur;
- same Media3 effect path for preview and export;
- apply after LocalCut transform/compositing effects so keyframed movement is blurred;
- bounded GPU memory on mobile;
- deterministic output for the same frame sequence/settings;
- `shutterAngle = 0` and `samples = 1` behave as passthrough;
- no new paid dependency;
- no schema migration;
- fail closed on invalid state/resource allocation.

## Non-goals

- optical-flow interpolation;
- synthetic sub-frame reconstruction;
- bidirectional/future-frame shutter sampling;
- changing clip duration or timestamps;
- CPU frame download for the normal path.

## Approaches considered

### A. Gaussian blur

Rejected. It blurs every pixel spatially even when nothing moves and would be a fake Motion Blur control.

### B. FFmpeg/export-only temporal filter

Rejected for the core implementation. It would break preview/export parity and make interactive editing misleading.

### C. Media3 custom temporal GPU effect — selected

Use the existing Media3 `GlEffect` extension point with a LocalCut-owned shader program and bounded history textures. The current input frame and copied historical frames are weighted and normalized into one output frame. This runs in the same effect chain used by preview and export.

Android Media3 1.11.1 exposes custom `GlEffect`/`GlShaderProgram` extension points and does not provide a built-in MotionBlur effect, so a custom implementation is required.

## Temporal model

The renderer keeps up to `effectiveSamples - 1` previous frames plus the current frame.

- requested samples remain `1..64` for project compatibility;
- `effectiveSamples` is limited by a mobile memory policy based on output pixel count;
- the current frame always has non-zero weight;
- historical contribution scales monotonically with `shutterAngle / 360`;
- weights are normalized so constant-color input remains constant color;
- before enough history exists, only available frames participate;
- history resets on configure/size change/release and must not leak across streams.

This is trailing temporal integration of actual decoded/rendered frames. It is not optical-flow or sub-frame reconstruction.

## Pipeline placement

`TransformEffectFactory -> Media3CompositingEffectFactory -> Media3EffectStackFactory`

`localcut.motion_blur` is created from `Media3EffectStackFactory`, so it sees transformed pixels and therefore blurs movement generated by LocalCut keyframes as well as movement present in source media.

## Memory policy

Use an explicit pure policy to calculate effective sample count.

Targets:

- never exceed requested `samples`;
- never exceed the hard implementation texture limit;
- reduce history at high resolution;
- always keep at least one current-frame sample;
- no silent allocation loop/retry.

The policy is unit-tested independently from OpenGL.

## UI

Add a `Movimento` effect-browser category only after the backend is renderable.

Expose `Motion Blur` with numeric controls for:

- shutter angle;
- samples.

The UI writes normal `EffectInstance` state and therefore uses the existing effect history/autosave path.

## Safety / failure behavior

- invalid parameters are rejected by `EffectRegistry`;
- GL allocation/shader errors surface as `VideoFrameProcessingException`;
- history resources are explicitly released;
- size/configuration changes drop old history;
- disabled effect is a no-op;
- no fallback to Gaussian blur.

## Acceptance criteria

1. `Media3EffectStackFactory.canRender()` accepts valid `localcut.motion_blur` and rejects invalid/animated unsupported variants.
2. `0°` or one sample is passthrough.
3. Pure temporal-weight tests prove normalized monotonic weighting.
4. Memory-policy tests cover 720p/1080p/4K and requested sample extremes.
5. Shader contract samples current + historical textures and normalizes weights.
6. Preview/export use the same effect object path.
7. UI exposes Motion Blur only after backend support exists.
8. Effect edit remains undoable/autosaved through existing effect commands.
9. Existing visual effects, Blend compositor, Tracking, preview, export and project compatibility do not regress.
